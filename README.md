# Travelers Backpacks: Stackable (tbstackable)

Автор: darkxwn. Аддон к Traveler's Backpack (Fabric, MC 26.3, мод 11.4.1).

## Что уже есть
**Этап 1:** 6 предметов-улучшений без вкладки и тумблера, рецепты (в т.ч. железо из дерева и из меди), lang en/ru, модели, временные текстуры 16×16 (заменить своими, имена те же).

**Этап 2 (серверная часть, компилируется против jar'ов игры 26.3, мода 11.4.1 и Fabric API 0.161):**
- `ItemStackHandlerMixin` + `BackpackWrapperMixin`: лимит стака хранилища = базовый лимит × множитель улучшения
- `ContainerContentsHelperMixin`: сохранение больших стаков. Стандартный кодек ItemStack принимает count не больше 99,
  поэтому при записи стак ужимается до обычного лимита предмета, а излишек пишется в компонент `tbstackable:extra_count`;
  при чтении всё склеивается обратно. Старые рюкзаки читаются как раньше.
- `UpgradeLockableSlotItemHandlerMixin`: улучшение нельзя вынуть (или заменить на более слабое), пока стаки не помещаются без него.
  Замена на тир не ниже текущего разрешена прямым кликом.
- Логика проверена тестами: `src/test/java/.../LogicTest.java` (запуск: `java LogicTest` после компиляции)

**Этап 2, клиентская часть (компилируется против клиентского jar 26.3):**
- `GuiGraphicsExtractorMixin`: счётчик больше 99 рисуется как "1.03k" / "27.6k" / "123k" / "1.05M" уменьшенным шрифтом,
  чтобы влезал в слот (суффиксы "k"/"M" и "к"/"М" берутся из lang)
- `BackpackTooltipComponentMixin`: превью по Ctrl складывает настоящие количества и больше не режет стак по 999 на второй слот
- `AbstractContainerScreenMixin` + `OverflowHighlight`: при попытке вынуть (или ослабить) улучшение, пока стаки не помещаются,
  слоты, которые нужно разгрузить, подсвечиваются красным на 3 секунды (последние 0.7 с плавно гаснут)

## Чего ещё нет
- Аудит остальных мест мода, где используется лимит стака: ContainerSorter, InvWrapper, RefillUpgrade, AbstractSmeltingUpgrade,
  ToolSlotItemHandler, CraftingTweaks. Сортировка пока может разбивать большие стаки.
- Проверка в игре: ничего из этого ещё не запускалось. Mixin'ы проверены по именам и сигнатурам целей, но не запуском.
- Возможный конфликт с Sophisticated Backpacks, если стоят оба мода: оба рисуют счётчики больше 99.

## Важно про данные
Если убрать мод из мира, где уже лежат стаки больше обычного лимита, компонент `extra_count` станет неизвестным,
и такой рюкзак может не загрузиться. Не удаляйте мод из миров с большими стаками.

## Сборка
Версии из ваших jar: Fabric API 0.161.0+26.3, Fabric Loader >=0.19.3, Java 25.
Каркас НЕ содержит build.gradle: версии Loom/Fabric API для 26.3 нужно брать из официального
генератора шаблона (fabricmc.net/develop/template). Дальше:
1. Сгенерировать шаблон: mod id `tbstackable`, пакет `com.darkxwn.tbstackable`.
2. Скопировать src/ из этого каркаса поверх шаблона (fabric.mod.json заменить нашим).
3. Положить jar Traveler's Backpack в libs/ и подключить как зависимость тем способом,
   который использует шаблон (modImplementation или implementation).
4. Для запуска в dev-среде добавить зависимости самого мода (forgeconfigapiport).

Серверная часть проверена компиляцией против реальных jar'ов (javac 25). Клиентская часть (StackUpgradeWidget)
без клиентского jar не проверялась. Mixin-аннотации проверены только по именам целей, не запуском игры.
